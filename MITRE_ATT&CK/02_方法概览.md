# [2] ATT&CK Evaluations 方法概览

> 官方页面：https://evals.mitre.org/methodology-overview
> 可信度标记说明见 [README](README.md)。

## 一、往年一直沿用的方法（ER1–ER7 公开资料一致，可信度较高）

1. **模拟真实攻击者**：MITRE 根据公开威胁情报，挑选真实攻击组织（或以其为原型）编写攻击剧本，在受控环境中逐步执行。
2. **以 ATT&CK 技术为单位记录**：每个攻击步骤对应一个 ATT&CK 技术或子技术，检查产品在这一步看到了什么。
3. **检测结果分级**（往年）：

   | 级别 | 含义 |
   |---|---|
   | None | 没检测到 |
   | Telemetry | 只有原始数据，没有告警 |
   | General | 有告警，但没说明是什么行为 |
   | Tactic | 告警能说明攻击者的意图（战术） |
   | Technique | 告警能精确到具体技术（最好的一级） |

4. **修饰标记**：
   - Configuration Change：测试途中改过产品配置
   - Delayed：检测结果延迟才出现
5. **防护评测**：看产品是否阻断了攻击、在哪一步阻断。
6. **公开透明**：方法和结果对所有人公开，厂商拿到的文档与普通用户相同。【官方】

## 二、ER7（2025）引入的变化

- 加入模拟的正常业务背景流量，开始关注误报。【第三方】，在 TES 中如何计分【待核实】

## 三、2026（ER8）的变化

- 从二元判断转为质量评分：告警质量、分析精度、平台速度、阻断时机、误报表现，**按技术的重要程度加权**。【官方】
- EDR / XDR / MDR / MSSP / SIEM / AI SOC 使用同一套场景、同一套指标。【官方】
- 具体评分公式见 [03](03_TES与IQI评分细则.md)。

## 四、理解要点

- 评测测的是"在这一组特定场景下的表现"，不是产品的全面能力。
- 检测分级的核心思想是**告警的上下文价值**：同样是检测到，能精确到技术的告警比只有原始数据有用得多。2026 的 DQI"覆盖度"延续了这个思想。【推断】
